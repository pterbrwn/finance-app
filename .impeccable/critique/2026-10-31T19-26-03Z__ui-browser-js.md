## Priority issues

1. **P1 — Scenario preview still overpromises what can remain unknown.** The UI says costs can remain unknown in the preview, while saving requires many of those values. Save does not list requirements; invalid submission reveals sections only after an attempt (`ui/browser.js:227`, `shared/scenarios.mjs:3`). Keep preview language separate from save guidance, list required fields before Save, and label which fields accept zero versus unknown. Suggested commands: `$impeccable clarify`, `$impeccable harden`.
2. **P2 — Mobile filter disclosure loses context.** The panel starts closed, but a filter change rerenders and closes it. While closed, it gives no active-filter indication (`ui/browser.js:152,294`). Preserve open state across rerenders and show an active-filter count. Suggested commands: `$impeccable adapt`, `$impeccable clarify`.
3. **P2 — Primary mobile results remain low in the viewport.** Transactions begins near the bottom of the 844px viewport and the budget result appears near the fold. Tighten the mobile page header and control spacing to move results higher. Suggested commands: `$impeccable layout`, `$impeccable adapt`.

## Personas and cognitive load

- First-time household member: can select Joint, but may assume the rough scenario preview can be saved with unknown costs.
- Power user: bulk review remains available; Cancel is safer. Month-change selection clearing was not reverified.
- Mobile user: search and the first transaction appear sooner, but filters hide active state and the first row starts near the viewport’s lower edge.

Cognitive load is moderate: task clarity improved, but hidden filter state and scenario save requirements still require inference. The emotional high point is a preview that preserves unknown costs; confidence drops when Save reveals additional requirements.

- Budget rows now separate plan, actual, and remaining amounts without the earlier desktop collision (`ui/browser.js:175`).

## Priority issues
1. **P1 — Hidden transaction selection can affect offscreen records.** Selections persist across search/category/account/date/review filters and pagination; bulk category changes submit all retained IDs. Clear selection when result scope changes, or pin a persistent count with a review list and explicit “all selected records” confirmation (`ui/browser.js:150`, `ui/browser.js:292`). Suggested command: `$impeccable harden`.
2. **P1 — Unsaved edits can disappear.** Shared dialog Escape closes a dirty form; direct view and month changes can rerender without the existing navigation guard. Add one consistent dirty-state guard for Escape, close, route, period, and profile changes; confirm only after meaningful edits (`ui/dialogs.mjs:3`, `ui/browser.js:62`, `ui/browser.js:292`). Suggested command: `$impeccable harden`.
3. **P1 — Transaction text contrast remains insufficient.** Axe found 47 contrast nodes at 390px: category selects 4.08:1, dates 3.07:1, and positive amounts 4.07:1. Darken these semantic text colors and verify rendered states (`ui/styles.css:1`, `ui/browser.js:124`). Suggested command: `$impeccable typeset`.
4. **P2 — Purchase scenarios still demand too much before showing value.** The intro invites unknown amounts to be left blank, while many fields are required, including some in collapsed sections. Use a short first step, allow unknown optional inputs, then progressively request details needed for more precise results (`ui/browser.js:224-226`). Suggested command: `$impeccable shape`.
5. **P2 — Budget and household context needs to meet the decision.** The global scope selector lacks visible explanation; incomplete budget surplus appears inside a dense final cell while the governing caveats sit below. Show scope as a labeled view filter and put “Incomplete estimate” beside the result, with detailed math expandable (`ui/browser.js:175`, `ui/browser.js:266`). Suggested command: `$impeccable clarify`.

## Persona red flags
- Nontechnical partner: the scenario asks for mortgage terms and required zeroes before a useful estimate, and may mistake an incomplete surplus for spendable cash.
- Keyboard or screen reader user: dirty Escape loses work; route changes restore focus to navigation without a confirmed page announcement (`ui/dialogs.mjs:3`, `ui/browser.js:266`).
- Mobile user: navigation works, but Transactions shows many filters and actions before records, with some 9–11px labels and very small tap areas (`ui/styles.css:1`, `ui/browser.js:150`).

## Minor observations
- Route changes should focus or announce the new heading.
- Smooth scrolling should respect reduced-motion preference.
- Sequential snapshot requests may merit profiling if actual latency is felt; one local run alone does not establish a performance issue.

## Questions to consider
- Should changing a transaction filter clear the current selection, or keep it with an always-visible review panel?
- Should the purchase scenario show a rough payment after the first four inputs, with confidence increasing as costs are added?

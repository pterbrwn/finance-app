## Persisted entity and ownership map

| Persisted entity | Storage | Owner / relationship rule |
| --- | --- | --- |
| Provider items | `items` table | Household connection; credentials stay in private runtime storage and are omitted from public and portable snapshots. |
| Accounts | `accounts` table | Explicit `profileId`; owns balance and default transaction/holding attribution. |
| Transactions | `transactions` table | `profileId` override, otherwise account owner; unresolved stays unassigned. |
| Holdings | `holdings` table | Explicit override, otherwise investment account owner; provider refresh preserves local override/history. |
| Profiles and plan state | `household_profiles`, `household_plan_state` | Stable IDs `peter`, `maddie`, `joint`; plan state is keyed by owner. `combined` is a view only. |
| Budget records and history | `budget_records`, `budget_change_history` | Profile is part of record/history key; custom category owner is retained by stable category ID. |
| Goals and allocations | State metadata payload | Goal has `profileId`; allocation and ledger owner derive from parent goal; funding account must be compatible. |
| Properties and mortgages | State metadata payload | Property has `profileId`; mortgage inherits its property owner and validates linked liability account. |
| Commitments and matches | State metadata payload | Commitment has `profileId`; payment match must share the same effective transaction owner. |
| Scenarios and goal/budget links | State metadata payload | Scenario has `profileId`; linked goals and budget writes must target the same profile. |
| Categories and category settings | `custom_categories` plus state metadata | System taxonomy is shared; custom category has a profile owner and stable ID; settings follow category ID. |
| Transaction splits and reimbursements | State metadata payload | Split inherits parent transaction owner; reimbursement requires both transactions to have the same effective owner. |
| Statement reviews and mortgage snapshots | State metadata payload | Review follows account; mortgage snapshot follows mortgage/property owner. |
| Category edit/import batches | State metadata payload | Ownership is the set of referenced transactions/accounts; personal views receive only wholly owned batches and personal undo checks the full batch. |
| Balance snapshots | State metadata payload | Stores `viewProfile` and attribution policy; legacy snapshots keep unknown provenance. |
| Operation replay records | `operation_results` and state metadata | Household-scoped by unpredictable operation ID; authenticated actor access is checked. Financial target profile is included in the payload digest. |
